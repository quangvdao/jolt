## Summary

An experiment in RV64I hash-based Jolt over binary fields has, with `specs/rv64i-binary-prover-kernels.md` (below, the kernels spec), performance-tier cores for the bitwise outer sum-check, the routers, the chunk products and the reduction of committed claims. Eight members of `specs/rv64i-binary-protocol.md` still have only a dense reference kernel: `SpartanOuterF128`, `SpartanInner`, the three members of batch 4, the two of batch 5 and `BytecodeReadAddress`. The reference tables of batch 4 have `2^(a + log_t)` entries, so no proof exists beyond about `2^10` cycles. This spec adds the cores of those eight to `jolt-rv64i-kernels`, as seven modules on the machinery, the source traits, the runner, the oracle and the unit table of the kernels spec, which it cites and does not restate. Per cycle the memory cores read the bytes of three groups that the one checked walk of the source writes, and one lifted word; no core reads a digit from the source, and no table has `2^a·T` entries. The initial RAM costs one lift per non-zero word and one bind per pair of its list in each phase. What is proportional to the size of the RAM, which the run fixes, is a lift and an accumulation per word of the final RAM and, in `RamCore`, one count per group of its first phase. No shared crate changes: `SplitLt`, `LazyFoldedRa` and the split equality serve as they are, and the read-write, value-evaluation and output kernels of `jolt-kernels`, which sample at integers and carry increments as integer differences, do not.

## Intent

### Goal

Build the cores of `SpartanOuterF128`, `SpartanInner`, `RegistersReadChecking`, `RamReadChecking`, `RamOutputCheck`, the two value evaluations and `BytecodeReadAddress`, with the views of the memory trace they share, each emitting exactly the round polynomials of its definition within a stated number of nanoseconds per cycle and with no table of `2^a·T` entries.

**Notation.** That of the kernels spec: `T = 2^log_t` cycles indexed by `j`, points low variable first, `eq(w, x) = Π_i (1 + w_i + x_i)`, every core binds low to high. In addition: `a` is the number of RAM address bits and `K = 2^a` the number of RAM words; `x = F128::from_raw(2)`; `r_bit` is a point of 6 coordinates and `lift(w) = Σ_{i<64} w[i]·eq(r_bit, i)`, a `WordLift` over the weights `eq_table(r_bit, None)`. Per cycle the memory trace gives a RAM index `addr_j < K`, a store bit `store_j` and three registers `rs1_j`, `rs2_j`, `rd_j` below 32; `U[j] = lift(Inc[j])` is the lift of the word `Inc`. With these,

`RegVal(k, j) = Σ_{j' < j, rd_j' = k, store_j' = 0} U[j']` and `RamVal(k, j) = lift(initial[k]) + Σ_{j' < j, addr_j' = k, store_j' = 1} U[j']`,

which are `RegistersVal(k, r_bit, j)` and `RamVal(k, r_bit, j)` of `specs/rv64i-binary-protocol.md` §3 under the witness contract of its §8.1: in characteristic 2, `(1 + Store)·Inc` is `Inc` on a cycle that is not a store and zero on a store. `ρ` is the number of visited bytecode rows per cycle, as in the kernels spec, `κ = K/T` the number of RAM words per cycle and `ν` the number of non-zero words of the initial RAM per cycle. A core's challenge point is written `(z, r')`: `z` for its row or address rounds and `r'` for its cycle rounds.

`a` is not chosen here. It is `log_K_ram` of the proof's layout, between 5 and 61 in the protocol, and the run fixes it as the least size that covers the I/O region, the image and the highest word a cycle accesses (`crates/jolt-rv64i-trace/src/adapt.rs`). The cores accept `1 ≤ a ≤ 32`, the values below 5 for tests. Above 32, `MemoryTrace::new` returns `MemoryError::UnsupportedAddressBits { bits, supported }`, a capability error distinct from those of a malformed group. The bound is `memory::MAX_ADDRESS_BITS`, which the adapter compares with `log_K_ram` before it prepares anything.

**Memory views.** The cores read the witness through the two source traits of the kernels spec. No trait is added and `CycleSource` gains no method: every fact these cores need per cycle is a digit column or a trace word, and a second trait would be a second way to state a column. The digits reach the cores as byte groups of `ValidatedTrace::prepare`, the one checked walk of the source: a *present* group holds one byte per column and cycle for columns of at most 8 bits whose digit is always `Some`, an *optional* group the digit plus one, or zero, for columns of at most 7 bits. A core takes a group by value and reads no digit from the source. Module `memory` holds the views.

`MemoryTrace::new(ram, registers, store)` takes three groups of one prepared trace: `ram`, a present group of the digit columns of the RAM index, low chunk first, of `a` bits in all; `registers`, a present group of three columns of 5 bits, `rs1`, `rs2`, `rd` in that order; `store`, an optional group of one column of zero bits, set where its byte is non-zero. It makes no pass over the cycles: it checks the counts and the widths of the columns and that the groups have one number of cycles, and holds them, `d_a + 4` bytes per cycle for `d_a` RAM chunks. That a RAM digit or a register is present on every cycle is the walk's check, which returns `SourceError::MissingDigit`: a cycle without an access carries index 0 and an absent operand register 0, as the witness contract has them. `MemoryTrace` is not generic over the source, so no memory core is. It is shared by `Arc`, with the register and store groups behind an `Arc` of their own, which is all `ValEvaluationCore` keeps. `into_ram_chunks(this: Arc<MemoryTrace>)` returns the RAM group to the chunk product of `RamRaProduct`, so that its bytes are written once, or `MemoryError::InUse` with the number of other handles while one exists; it never copies. A core gives up its handle on the thread that drives it, at a point that does not depend on the length of the trace: `RegistersCore` and `RamCore` at their first cycle round, `ValEvaluationCore` at the return of `new`. The register and store bytes may outlive the call, since `LazyFoldedRa` drops its source on a thread of its own at its fourth bind and a trace of fewer than four binds never reaches one; the RAM group does not wait for them.

- `inc_lift(trace, word, lift)` returns `U`, one element per cycle, for the trace word `word`. A full optimised proof does not call it: the routers hold the lift of `Inc` at the same `r_bit`, and after `claims_pass` `RetainedWordLifts::into_word` gives that table up as `U`. `inc_lift` serves a member whose batch 3b ran on reference kernels, and the tests and benchmarks of one core.
- `fold_words(words, lift, point)` returns, for `2^m` words and a point of `n ≤ m` coordinates, the `2^(m−n)` elements `out[c] = Σ_{low < 2^n} eq(point, low)·lift(words[c·2^n + low])`.
- `address_column(memory, point)` returns `out[j] = eq(point, addr_j)` for a point of `a` coordinates.
- `row_weights(plan, weight)` returns, over the bytecode rows of a `ScatterPlan`, `R[k] = Σ_{j: bytecode_index(j) = k} E(j)` with `E(j) = eq(point, j)` for `RowWeight::Eq(point)`, and with `E(j) = eq(point, j − 1)` for `j ≥ 1`, `E(0) = 0`, for `RowWeight::Next(point)`, the convention of `ChunkWeightTerm::Next`.

**Packed rows.** A `PackedBlock { row_variables, words, flag, powers }` describes a block of `2^μ` rows with values in `F128`, `μ = row_variables` equal to 4 or 5: `words`, two trace words of the source; `flag`, an optional group of one column of zero bits, with `f_j = 1` where its byte is non-zero; and `powers`, present groups whose columns, taken in order, are `P` digit columns of at most 4 bits, with `6 + P ≤ 2^μ`. The groups are those of `ValidatedTrace::prepare` on the same source and are taken by value. With `pack(w) = F128::from_raw(w as u128)`, the rows of cycle `j` are

| Row | `Az` | `Bz` | `Cz` |
|---|---|---|---|
| 0 | `f_j` | `pack(word_0(j))` | 0 |
| 1 | `1 + f_j` | `pack(word_1(j))` | 0 |
| 2 to 5 | 0 | 1 | 0 |
| `6 + p`, for `p < P` and `d` the digit of power column `p` at `j` | `x^d` | `x^(2d)` | `x^(3d)` |
| the rest | 0 | 0 | 0 |

A power of `x` below `x^46` is `F128::from_raw(1 << e)`. For `τ` of `μ + log_t` coordinates, row variables first, `OuterF128Core` proves

`Σ_{i < 2^μ, j < T} eq(τ, (i, j))·(Az[i, j]·Bz[i, j] + Cz[i, j])`

in `μ + log_t` rounds of degree 3 and returns `Az`, `Bz`, `Cz` at `(z, r')`; `into_groups` returns the groups of the block, which are the chunk groups later batches take. It serves `SpartanOuterF128`, whose block has the two key gates in rows 0 and 1, four residual rows whose `Az` is zero on an honest witness, and one power row per chunk (invariant 1).

**Pair sums.** `PairSumCore::new(pairs)` takes 1 to 8 pairs `(H_t, R_t)` of tables of one length `2^n`, `n ≥ 1`, proves `Σ_t Σ_k H_t[k]·R_t[k]` in `n` rounds of degree 2 and returns every table at the challenge point. It serves `SpartanInner`, with three pairs over the 1,024 witness columns, and `BytecodeReadAddress`, with four pairs over the bytecode rows. For the first, `routed_columns(shapes, folds)` returns `out[o] = Σ_ρ Σ_{(o, s, h) ∈ route_ρ} Fold_ρ[s, h]` over the output domain of the shapes, from the tables `fold_pass` returns.

**Register reads.** For coefficients `c = (c_0, c_1, c_2)` and `Sel[k, j] = c_0·[rs1_j = k] + c_1·[rs2_j = k] + c_2·[rd_j = k]`, `RegistersCore` proves

`Σ_{k < 32, j < T} eq(r_cycle, j)·Sel[k, j]·RegVal(k, j)`

in `5 + log_t` rounds, the five address variables first, with messages of degree 2 in the address rounds and 3 in the cycle rounds, and returns `Sel` and `RegVal` at `(z, r')`. `register_claims(trace, columns, z, row_weights)` returns `Σ_k R[k]·eq(z, reg(k))` for `reg` each of three `by_row` columns of at most 5 bits, read by bytecode row with `row_digit`; a row whose digit is `None` contributes nothing. With the columns of `rs1`, `rs2`, `rd` and `R = row_weights(plan, Eq(r'))` these are the three selector columns at `(z, r')`: a row without a digit is then a row no cycle visits, by the walk's check on the register group, and its `R[k]` is zero.

**RAM reads.** `RamCore` proves

`Σ_{k < K, j < T} eq(r_cycle, j)·[addr_j = k]·RamVal(k, j)`

in `a + log_t` rounds, address variables first, with the same degrees, for `1 ≤ a ≤ 32`, and returns `Ra(r') = Σ_j eq(r', j)·eq(z, addr_j)` and `RamVal(z, r')`. Every cycle is a read of its index, a cycle without an access of word 0 at its actual value. The initial RAM is given as the canonical vector of `specs/rv64i-binary-protocol.md` §7, pairs `(index, word)` with strictly increasing indices below `K`, and every word without a pair is zero; the core makes no table of `K` elements from it. `into_address_column` returns the table `eq(z, addr_j)` over the cycles, unbound. `RamOptions { phase_bits, block_entries }`, by default 10 and 4,096, with `phase_bits` in `1..=12` and `block_entries ≥ 1`, changes no message.

**RAM output.** For final words `final[k]`, a range `mask` of words and the words `io` of the public memory on that range, `RamOutputCore` proves

`Σ_{k < K} eq(τ, k)·[k ∈ mask]·lift(final[k] ^ io[k])`

in `a` rounds of degree 3, the equality factor, the indicator of the mask and the lifted difference each extended on its own, for `1 ≤ a ≤ 32`, and returns `Σ_k eq(z, k)·lift(final[k])`, the extension of the whole final RAM. An empty mask is accepted: the messages are zero and the value is the same fold.

**Value evaluation.** With `lt(j, r)` the extension of `[j < index]` at `r`, `Rd[j] = eq(a_reg, rd_j)`, `S[j] = store_j` and a table `Ra` over the cycles, `ValEvaluationCore` proves, as two members of one batch,

`Σ_j lt(j, r_cycle)·Rd[j]·(1 + S[j])·U[j]` and `Σ_j (c_val·lt(j, r_cycle) + c_final)·Ra[j]·S[j]·U[j]`

in `log_t` rounds of degree 4 and returns `Rd`, `S`, `U` and `Ra` at `r'`.

### Invariants

Invariants 1 to 12 of the kernels spec hold for every item of this one. These are added or extended:

1. **Honest inputs (extends 6).** Every core of this spec is definitional for the tables and groups it is given, a violated key gate included. Two preconditions are not checked. The first is the caller's: the groups, the lifted word and the address table a core is given belong to one trace. A group records its columns, widths and cycle count and not the source it was prepared from, so a core given the groups of another trace proves the sum of that trace. The second is the adapter's. Rows 2 to 5 of the protocol's block, rows 132 to 135 of its system (`crates/jolt-rv64i-arith/src/rows.rs`), carry `pack(RdResidual)`, `pack(RamResidual)`, `pack(NextPCResidual)` and `pack(ControlResidual)` in `Az`, and `PackedBlock` has zero there. The two agree when the four forms are zero on every cycle, which an honest witness satisfies and no core checks. On a witness that violates one, the `az` of `OuterF128Core` is that of another table, and what catches it is `SpartanInner`, whose matrix weights the adapter builds from all the rows: at the final check of batch 2 the claim that batch 1's values fix and the weighted witness columns disagree, except with the soundness error of the protocol over the challenges.
2. **Nothing of `2^a·T` entries.** Storage and time are linear in `T`, in `K` and in `bytecode_rows()`. One core is linear in `K` on every trace: `RamOutputCore` lifts and folds each of the `K` final words once. It holds field tables only for the window of its mask and the cells that pad the window to pairs, so a mask of the whole RAM makes that window `K` cells. `RamCore` is linear in the entries, in the pairs of its initial lists, in the counts of its first phase, `2^(a − w_0)` per range of chunks, and in its checkpoint cells, exactly `2^w_p·B_p` in phase `p` with `B_p` as in Design, which repeated blocks of even one group can take above `K`.
3. **Representation (extends 3).** Beyond the tables that invariant names, a table of `F128` exists here as: `U`, one table per proof, which in a full optimised proof is the allocation `source_lift` made for the word `Inc`; the two cycle tables of `RegistersCore` and of `RamCore` from their first cycle round; one element per entry of `RamCore`, with at most one entry per cycle; the tables of `OuterF128Core` from its last row round; the halves of `U` and `Ra` in `ValEvaluationCore`; the pairs of a `PairSumCore`; the outputs of the views. No core copies a digit: what it reads is a group of the walk, `d_a + 4` bytes per cycle for the memory trace and `P + 1` for the packed block. The walk itself writes one pair of digits twice: the two `Pos` digits are in a present power group of the block, as digits, and in the optional group of the routers' selectors, as digit plus one, because a group has one encoding and each core takes its group by value. At the reference layout the request is therefore 25 bytes per cycle: the 18 of the kernels spec, three registers, the store bit, the `KeysDiffer` flag and the second pair of `Pos` bytes.
4. **Tables in cache (extends 7).** The exceptions here are: the tables indexed by bytecode row or by RAM word; the checkpoints of `RamCore`, one arena read once per block and round; and, in `OuterF128Core` on a block of more than 16 power columns, the histograms of its first pass (257 elements each: 56 KiB at 12 columns, 80 at 16, 128.5 at 24) and the pair tables of its streamed rounds (12 KiB per pair of columns: 72 KiB at 12, 96 at 16, 144 at 24). Bucket tables that one loop iteration updates, by read, XOR and write, at an equal key are never a multiple of 4,096 bytes apart: the 14 histograms of `OuterF128Core` are byte positions of `BucketPlacement::Byte` of the kernels spec, and the three histograms of `register_claims` are adjacent in one array, 512 bytes apart. The statement is about those tables alone: a last row round and a bind write several tables in one iteration as plain stores, and the tables of the streamed rounds are read only. The state of a register chunk (512 bytes) and of a RAM block (16 KiB at `phase_bits = 10`) is one array, in which a store followed by a load of one cell is a dependency that no placement removes and the benchmarks measure (Performance).
5. **One variable order (extends 12).** `round::eq` gains `split_lt`. No other module reverses a point or constructs a `SplitLt`.
6. **Options change no message.** The messages and final values of `RamCore` are those of its definition for every `RamOptions`, every thread count and every partition into blocks.
7. **No shared-crate change (extends 9), no new dependency (extends 10).** The crate uses `SplitLt`, `LazyFoldedRa` and `ChunkIndexSource` of `jolt-kernels` and the split equality of `jolt-poly` as they are.
8. **One walk of the digits.** No constructor, view, pass or round of this spec calls `digit` on the source. What is read from the source per cycle is a trace word: `Inc` once, by `inc_lift`, only where the routers left no lift of it; and the two words of a `PackedBlock` in the first pass of `OuterF128Core` and in each of its row rounds from round 2 on. `register_claims` reads `row_digit`, once per bytecode row.

No `jolt-eval` invariant changes: nothing here is reachable from the existing prover.

### Non-Goals

Implementations of `SumcheckKernel` and `PrepareKernel` for the eight relations and their acceptance against the reference kernels, which a separate spec owns; the tables an adapter builds from public data (`H_t` of `BytecodeReadAddress`, the matrix weights and public columns of `SpartanInner`, the placement of the histograms of `fold_pass` in `direct`, `InitEval`); a RAM of more than `2^32` words, which the protocol admits and `MemoryTrace::new` refuses with a typed error before any core is built, the one place the bound is checked (`RamOutputCore` indexes its words by `usize` and has no bound of its own); a sparse form of the final RAM, which the witness holds as `K` dense words; any change to the protocol, to `prove_batch` or to a shared crate; witness generation; any commitment.

## Evaluation

### Acceptance Criteria

"By summation" and "rejected" are as in the kernels spec: computed from the definitions in Goal with `oracle` on dense tables built in the test, and refused by the prover's round check or by the verifier of `jolt-sumcheck`. A core takes its value at 1 from the claim, or from its own sum where the equality factor vanishes there. Seeded points have pairwise distinct coordinates.

The memory criteria share one *separating trace* per size, seeded and then fixed in the places that make each of these mistakes change a value: two operands exchanged (the three coefficients differ, and a cycle reads two distinct registers whose values differ); a store applied as a register write (a store with non-zero `U` whose `rd`, in one case register 0, is read later); the address point consumed backwards (an accessed address whose bits are not a palindrome); the initial RAM ignored (a non-zero initial word that is loaded and never stored, and a non-zero word 0 under a cycle without an access); `Next` shifted the wrong way (cycles 0, 1 and `T − 1` at three distinct bytecode rows). Each requirement applies from the smallest `log_t` and `a` that can hold it. The grids below are bounded: the oracle copies and rebinds its dense tables at every round.

- [ ] **Memory views.** For `log_t` of 3 and 8 on the separating trace, with the RAM index as one chunk of 1 bit, two of 4, one of 8 with one of 4, and five of 4, each a view of the synthetic trace (Performance, "Synthetic memory"), on groups of `ValidatedTrace::prepare`: the index, the registers and the store bit that `MemoryTrace` gives at every cycle equal the digits of the source, and `into_ram_chunks` returns the bytes it was given; `inc_lift`, `fold_words` on `2^12` words for every `n` from 0 to 12, `address_column` and `row_weights` in both variants equal their definitions by summation, entry by entry.
- [ ] **Packed rows.** For `μ = 4` with `P` of 0, 1, 2, 5 and 10 and `μ = 5` with `P` of 0, 1, 2, 12, 13 and 26, `log_t` from 1 to 6, power columns of 1 to 4 bits, and traces with satisfied and with violated key gates: every round's coefficients equal the round polynomial of the dense table of `2^μ·T` rows by summation, `final_values` equal `Az`, `Bz`, `Cz` at the challenge point, and the one-member proof verifies from the claim by summation. The power columns come as one group and as two. Besides seeded `τ`: the all-zero and the all-one point, and seeded points with one row coordinate or one cycle coordinate set to 0 and to 1; and at `μ = 4`, `log_t = 1`, `P ≤ 2`, every `τ` in `{0, 1}^5`. A proof with one coefficient changed is rejected. `into_groups` returns the bytes the block was given.
- [ ] **Packed rows, smallest case.** `μ = 4`, two cycles, no power column, `τ = 0`; the flag set at cycle 0, `word_0(0) = 2`, `word_1(0) = 0`. The claim is `F128::from_raw(2)` and the first message is `x·(1 + X)^3`, with the coefficients `[2, 2, 2, 2]` as raw values. A core that exchanged the two words would send `[0, 2, 0, 2]`.
- [ ] **Pair sums.** For 1 to 8 pairs of 2 to `2^10` entries: coefficients and final values by summation, the proof verifies, a changed coefficient is rejected. For the one pair `H = [1, 2]`, `R = [3, 1]` in raw values the claim is 1 and the message is `[3, 7, 6]`.
- [ ] **Routed columns.** For the five shapes of the kernels spec's criteria with seeded `route` sets and the tables of `fold_pass`: `routed_columns` equals `Σ_j eq(r_cycle, j)·Σ_ρ Σ_{(o, s, h) ∈ route_ρ} Source_ρ[s, j]·Select_ρ[h, j]` by summation over the cycles; with every `route` empty it is zero.
- [ ] **Register reads.** For `log_t` from 1 to 8 on the separating trace, which from `log_t = 6` reads every register through each operand and writes it, register 0 included: every round's coefficients and the final values equal their definitions by summation on the dense table of `32·T` entries; `register_claims` equals the three selector columns at `(z, r')` by summation, and `c_0·rs1 + c_1·rs2 + c_2·rd` of its values equals the core's `Sel`. Smallest case: two cycles, `r_cycle = (1)`, `c = (1, 0, 0)`, cycle 0 writes register 1 with `U[0] = 2` and is not a store, cycle 1 has `rs1 = 1`. The claim is 2 and the first message is `[0, 0, 2]`.

### Testing Strategy

The ground truth is `oracle`, on dense tables the test builds from the definitions of Goal: `32·T` and `K·T` entries for the read checks, `2^μ·T` rows for the packed block. It shares no view, checkpoint, entry or round assembly with the cores. Each test asserts an algebraic identity against it, a rejection or a typed error, clauses (c) and (e) of `.claude/skills/test-policy/SKILL.md`; none compares one setting of `RamOptions`, one thread count or one form of a message with another, and every setting is tested against the same summation. The smallest cases are literals computed by hand from the definitions. One that names a wrong core tells that core apart and no other; exchanged operands are the separating trace's part. The tests of the kernels spec and of the shared crates pass unchanged. The `host` and `zk` modes do not apply.

Rustdoc on the public items states the contracts of the surface table, and in particular what is not checked: that `inc` is the lift of the word the protocol means and `lift` the lift it was made with; that `initial`, `final_words` and `io` are the RAM of the statement; that `ram_ra` is the address column of the same trace; and, on `PackedBlock` and `OuterF128Core`, the four residual rows of invariant 1 by name with the check of batch 2 that covers them. The adapter of `SpartanOuterF128` and the reference kernel it replaces state the same substitution in their own rustdoc when that adapter is written.

### Performance

The machine, the sizes, the runner, the id form `<bench>/<profile>/<log_t>/<threads>`, the profiles, the unit table with its two price points and the rule that derives a threshold from a model are those of the kernels spec, Performance. This section states operation counts in its symbols and applies its rule; it adds no unit and replaces no row.

**Synthetic memory.** `SyntheticTrace` gains columns and words, appended, so that no existing column, word, profile or benchmark changes: the digit columns go from 21 to 29 and the trace words from 6 to 8, `Inc` stays word 5, `Store` column 17 and `KeysDiffer` column 18, and `small_values` keeps its distribution and its own stream of the generator. Columns 21 to 23 are three `by_row` register columns of 5 bits, from bits 0–4, 5–9 and 10–14 of bytecode word 0. Columns 24 to 28 are five normalised RAM chunk columns, equal to columns 5 to 9 on a cycle with an access kind and `Some(0)` elsewhere, the witness contract's index 0; columns 5 to 9, which are non-zero on a cycle without an access, stay for the benchmarks that have them. Words 6 and 7 equal trace words 0 and 1 where the `KeysDiffer` flag is clear, respectively set, and are zero elsewhere, so that both key gates hold. `memory_columns()` names the normalised RAM columns, the register columns and the `Store` flag. `packed_columns()` names the `KeysDiffer` flag, words 6 and 7 and twelve chunk columns for a block of `μ = 5`: the five bytecode chunks, the same five normalised RAM columns and the two `Pos` columns. The RAM group that `into_groups` returns is then the one `MemoryTrace::new` takes, as in a proof. One profile is appended, `chained`: `all_rows` except that bits 0–4 of bytecode word 0 of a row are bits 10–14 of the row before it, modulo `bytecode_rows()`, so that a cycle reads through `rs1` the register the cycle before wrote, and that the cycle after a store carries the store's RAM chunks, so that an access there reads the cell written. `SyntheticMemory::new(trace, a, seed)` replays each normalised RAM index modulo `2^a` and gives the initial RAM as one seeded non-zero pair per word, so that `ν = κ` and the list is as long as it can be, exactly `K = 2^a` final words in an `Arc` (the initial words with the increments of the stores applied), the mask `0..min(K, 2^12)` and the final words on it as `io`. The benchmarks are at `a = 20`, on the trace itself. A test of another domain prepares the same indices through a test-only `CycleSource` view of `SyntheticTrace`, which exposes the index modulo `2^a` in chunks of the widths the test asks for and carries the fixed edits of the separating trace, with its cycle digits and its row cache consistent. On `local` and `all_rows` a cycle is a load with probability 0.25 and a store with 0.10; `RamCore` then has `f = 0.45` entries per cycle, of which `s = 0.10` are stores (Design, "RAM reads").

`outer_f128`, `ram`, `ram_output` and `val_evaluation` run on `local`; `registers`, `bytecode_address` and `memory` on `all_rows`, because they scatter by bytecode row. ## Design

### Architecture

The round messages, the lifts, the equality helpers, the chunks of `CycleChunks`, the scratch pool and the scatter are those of the kernels spec, Design. What follows is what each core adds.

#### Memory views

`MemoryTrace` holds the three groups as the walk wrote them and adds no table. A read of a cycle's index shifts and ORs the `d_a` bytes of its RAM digits, two word operations per chunk; `RamCore` makes it once per cycle when it builds its entries and `address_column` once. The registers and the store bit are single bytes, three adjacent and one in a stream of its own, which the scans of `RegistersCore` read in cycle order. `fold_words` forms `eq(point, low)` as a product of two half tables: the inner sum is an `fmadd` chain against the low half, reduced once per block and multiplied by the high half. A fold of no coordinate lifts and does nothing more. `address_column` splits the address into pieces of at most 11 bits, with one table per piece: two pieces and one multiplication for `a ≤ 22`, three and two above. `row_weights` passes the weight `E(j)`, a product of two half-table entries, to `ScatterPlan::scatter`; for `Next` the index is `j − 1` and cycle 0 has weight zero.

#### Packed rows

*First pass.* With `e_j = eq(τ_cycle, j)` formed by one multiplication, the pass accumulates the four gate sums `G[w][f] = Σ_{j: f_j = f} e_j·pack(word_w(j))`, the flag sum `Φ = Σ_j e_j·f_j`, one histogram of `e_j` per pair `π` of power columns `(2π, 2π + 1)`, keyed by the byte `d + 16·d'` of their digits, and, for every two pairs that share a block of four rows (pairs `π` and `π + 1` with `π` odd), four histograms keyed by one digit of each. A last column without a sibling and a last pair without a second pair in its block are the cases of "Absent rows" below. The digits are the bytes of the power groups, and the key of a pair is formed from two of them at each read; no key is stored. At 12 power columns that is 6 pair histograms and 8 cross histograms, 14 bucket updates per cycle in 56 KiB of scratch per worker; `Φ` and the gate sums are scalars in the accumulators of a chunk and not entries of a table. A cycle writes all 14 histograms, and writes several at an equal key whenever digits repeat, as the zero digits of a small index do. The histograms are therefore byte positions of `BucketPlacement::Byte`: histogram `n` starts at `position_offset(n)`, 257 elements after the last, and the scratch array of a worker has `position_offset(N)` elements for `N` histograms. Two entries then lie a multiple of 4,096 bytes apart exactly when the difference of their histogram numbers and that of their keys sum to a multiple of 256, which at an equal key no two of fewer than 256 histograms do. Unequal keys can still coincide, as the kernels spec says of its own tables; the placement removes the case that repeats on every cycle.

*Row rounds 0 and 1* come from those statistics. The round polynomial is `l(X)·q(X)` with `l` the linear factor of `eq(τ, ·)`, and `q`, of degree 2, is given by `q(0)`, its leading coefficient and `q(1)`. The third comes from `recover_q_one` of the split equality: from the claim `l(0)·q(0) + l(1)·q(1)` when `l(1)` is non-zero, and from the core's own sum when `l(1)` is zero, which happens when the round's coordinate of `τ` is 0 or an earlier challenge has made the equality factor vanish. The helper then checks the claim against `l(0)·q(0)`, and a disagreement is the round-check error of the core. The sum for `q(1)` is the sum for `q(0)` taken over the second cell of each pair in place of the first: from the same statistics in rounds 0 and 1, and by one more accumulator in the pass of a streamed or cycle round. A pass forms it only in a round whose `l(1)` is zero, so the counts of Performance, which are those of a round with `l(1)` non-zero, do not carry it. Every core of this spec whose message has an equality factor does the same: `OuterF128Core` in all its rounds, `RegistersCore` and `RamCore` in their cycle rounds, `RamOutputCore` in all of its. In round 0, with rows paired as `(2y, 2y + 1)`: the gate pair has `q(0) = G[0][1]` and the leading coefficient `G[0][0] + G[0][1] + G[1][0] + G[1][1]`; the two pairs of unit rows contribute nothing; pair `π` of power rows has `q(0) = 0` and the leading coefficient `Σ_κ Hist_π[κ]·(x^d + x^d')·(x^(2d) + x^(2d'))`. In round 1, after `r_0`, a folded power pair is `A_π = (1 + r_0)·x^d + r_0·x^d'`, and `B_π`, `C_π` likewise, as functions of the key. The block of the gate pair and a unit pair has `q(0) = Σ_f (f + r_0)·((1 + r_0)·G[0][f] + r_0·G[1][f])` and the leading coefficient `q(0) + Φ + r_0`; the block of a unit pair and power pair 0 has `q(0) = 0` and the leading coefficient `Σ_κ Hist_0[κ]·A_0·(1 + B_0)`; a block of two power pairs has `q(0) = Σ_κ Hist_π[κ]·(A_π·B_π + C_π)` and the leading coefficient `Σ Hist_π·A_π·B_π + Σ Hist_π'·A_π'·B_π'` plus the cross term `Σ_j e_j·(A_π·B_π' + A_π'·B_π)`, which is a sum of four terms each a function of one digit of each pair, read from the four cross histograms. Each pair or block is weighted by the equality factor of its remaining row variables, whatever the coordinates of `τ`. A third round from statistics would need the pairwise histograms of four pairs (Alternatives).

*Absent rows.* Rows `6 + P` to `2^μ − 1` are zero in the three matrices. An absent row is not a power row of digit 0, whose three entries are 1, and no digit is invented for it. When `P` is odd the last power column has no sibling and its pair is a half pair: its histogram is keyed by its one digit; in round 0 it has `q(0) = 0` and the leading coefficient `Σ_d Hist[d]·x^(3d)`, the product of the differences `x^d` and `x^(2d)` against a zero row; from round 1 on its folded rows are `(1 + r_0)·x^d`, `(1 + r_0)·x^(2d)` and `(1 + r_0)·x^(3d)`. A block of four rows whose second pair is a half pair has two cross histograms, one per digit of its first pair, in place of four. A block whose second pair is absent, as that of pair 5 is at 12 columns, has none: its `q(0)` is `Σ_κ Hist_π[κ]·(A_π·B_π + C_π)` and its leading coefficient `Σ_κ Hist_π[κ]·A_π·B_π`. The tables of the streamed rounds are built the same way, with zero for a missing row.

*Streamed rounds.* From round 2 to round `μ − 2` the pass reads the bytes of the power groups, forms the keys and reads, per matrix and pair of columns, one table of 256 elements that holds the pair's two rows folded at the challenges so far. One lookup per pair and matrix (18 at 12 columns) and one by the flag give `Az` and `Cz` of every cell; the gate's `Bz` is two multiplications of a weight by a packed word, read from the source. The products of a cycle are accumulated unreduced, reduced once for `q(0)` and once for the leading coefficient, and multiplied into the block sums against the low half of the split equality.

*Last row round and cycle rounds.* Round `μ − 1` has two cells. The pass materialises `Az`, `Bz`, `Cz` of both, six tables of `T` elements, forms the message from them and drops its handle of the trace; the bind writes into the tables of the first cell. The groups stay with the core, unread, until `into_groups`. The cycle rounds are those of `OuterF2Core`: `5 M + 2 A` per pair.

#### Pair sums and routed columns

`PairSumCore` computes, per pair of adjacent entries and pair of tables, `H_0·R_0` and `(H_0 + H_1)·(R_0 + R_1)` by `fmadd` into two accumulators, takes the value at 1 from the claim, and binds between two buffers, in parallel over the entries of tables as long as the bytecode. `routed_columns` adds one entry of `Fold_ρ` into `out[o]` per route triple, through `RouterShape::fold_index`, the crate-visible function that gives the index of `(s, h)` in a shape's table; the index is not written twice.

For `SpartanInner` the pairs are `(M, routed)`, `(M, direct)` and `(M, public)` over the 1,024 columns, `M` being the matrix weight. `routed` is `routed_columns` of the tables of one `fold_pass` at `r_1`, which therefore runs before batch 2 and serves batch 3a as well. `direct` needs one histogram of `eq(r_1, ·)` per chunk column and one for the `KeysDiffer` flag. The pass is given the RAM chunk columns, the two `Pos` columns and the flag as its `histogram_columns`. Those eight are among the eleven that the benchmark of the routers' pipeline requests, read out of a shape's table where a shape has the column and bucketed per cycle where none has. The five bytecode chunk columns are not requested. A cycle's digits there are the chunks of its bytecode index, so the adapter adds `ra_fold[k]` into one bucket per chunk for every bytecode row `k`: `ρ·5 Bk` per cycle, 0.75 ns at `log_t = 22` and 3.0 at 20, against `5 Bk` for five more histograms over the cycles. That pass is the adapter's, no benchmark of this spec covers it, and `ra_fold` is kept until it has run. For `BytecodeReadAddress` the pairs are `(H_Router, R_Router)`, `(H_Read, R_Read)`, `(H_Val, R_Val)` and `(Pc, c.Entry·R_Entry + c.Next·R_Next)`, the last because `H_Entry` and `H_Next` are multiples of the one table `lift(row.pc)`. `R_Router` is the `row_weights` that `claims_pass` returns at `r_3`; `R_Read` and `R_Val` are `row_weights` at `r_4` and `r_5`; `R_Next` is `row_weights(Next(r_3))`; `R_Entry` is 1 at `bytecode_index(0)`. The member's one value is the sum of the products of the four pairs of final values.

#### Register reads

*Address rounds.* Round `i` binds bit `i` of the register index. Let `V_i[m, j]` be `RegVal` with its low `i` bits bound at the challenges so far, a table of `32 >> i` cells per cycle, and `p = c_x·eq(r_{<i}, low_i(x))` the weight of an operand `x` of cycle `j`, with `m = x >> i`. The message has degree 2:

`s(0) = Σ_j e_j Σ_{x: m even} p·V_i[m, j]`, and the leading coefficient is `claim + Σ_j e_j Σ_x p·V_i[m ^ 1, j]`,

with `s(1)` from the claim. The core never holds `V_i` over the cycles. It holds the cells at the start of every chunk of cycles, built at construction by one pass (`delta[rd_j] ^= U[j]` on a cycle that is not a store, then a running XOR over the chunks) and bound at each challenge, 31 multiplications per chunk in all. A round is one scan, parallel over the chunks: each chunk starts from its checkpoint, and per cycle reads the cell and its sibling for the three operands, six terms taken from the state before the cycle, and then, only on a cycle that is not a store, applies the write `V[rd_j >> i] ^= eq(r_{<i}, low_i(rd_j))·U[j]`. A read of an absent operand is a read of register 0 at its actual value, and a write applies to register 0 as to any other. In round 0 the weights are the three coefficients, applied per block, so a cycle costs six `fmadd` against the low half of the split equality. In rounds 1 to 3 the weights come from three tables of `2^i` entries; the six products of a cycle are accumulated unreduced, reduced twice and multiplied into the block sums. Round 4 has two cells, `V_0` and `V_1`, and uses them: the weights of the three operands are added by cell into `S_0` and `S_1`, and the cycle contributes `S_0·V_0` to `s(0)` and `(S_0 + S_1)·(V_0 + V_1)` to the leading coefficient, which is the same quantity as the one above, two multiplications in place of six products and two reductions.

*Cycle rounds.* After round 4 the checkpoints are one element per chunk, the value of `RegVal(z, ·)` at the chunk's start. One pass fills `Sel[j] = Σ_x c_x·eq(z, x_j)`, three lookups, and `RegVal(z, j)`: a chunk starts from its bound checkpoint, which excludes the chunk, and writes the element of a cycle before it applies that cycle's update `eq(z, rd_j)·U[j]`, which a store does not have. The `log_t` rounds are `Σ_j eq(r_cycle, j)·Sel[j]·RegVal(z, j)` in the form `l·q`.

`register_claims` adds `R[k]` into one of 32 cells per operand and bytecode row, in parallel over the rows with one array per worker, merges the arrays and takes three inner products with `eq_table(z, None)`. The three histograms of a worker are one array of 96 elements, so that two of them written at one register lie 512 or 1,024 bytes apart. The core does not return the three columns separately because it binds their combination; `R = row_weights(plan, Eq(r'))` is needed by batch 6a in any case.

#### RAM reads

*Entries.* An entry is a weight `A`, an address, its rank in the time order and the mark of a store; a store has an increment `D` beside it. Entries and the lists `Init_p` are private structures of arrays: `F128` weights or values beside `u32` addresses, ranks or cells, with one checked length, and the store marks in a packed bitset. A tuple or a struct that held an `F128` would be 32 bytes where these are 24 and 20. The increments are one compact vector in the order of the stores: a block records its starting offset in it and a scan advances the offset only at a marked store. A store has one entry, with `A = e_j` and `D = U[j]`, and reads its cell before it updates it. A cycle that is not a store and has a non-zero index has one, with `A = e_j`. The cycles that are not stores and have index 0 are merged by interval. An interval is the cycles strictly between two consecutive stores of the trace, to whatever address, with the cycles before the first store and those after the last as the two outer intervals; all cycles of index 0 in one interval share one entry, with `A` the sum of their `e_j` and the rank of the first of them, whatever loads of other words lie between them. The merge is exact in every round because no cell changes inside an interval. Merging between two stores to word 0 alone would not be: a store to another word changes the cell into which word 0 is bound. Entries are produced per chunk of cycles, so an interval that crosses a chunk boundary has an entry on each side, and no entry is split by a block. The entries per cycle are therefore at most the stores, the other cycles of non-zero index, one per store for the intervals, and `2^−12` for the chunks. On `local` that bound is `f = 0.10 + 0.25 + 0.10 = 0.45`, which the model prices; the count expected of the profile's independent mix is 0.437.

*Phases.* The address bits are bound in `⌈a/ℓ⌉` phases, `ℓ = phase_bits`: phase `p` binds the `w_p = min(ℓ, a − ℓ·p)` bits from bit `ℓ·p`. In phase `p` an entry belongs to the group `address >> (ℓ·p + w_p)` and its cell is the `w_p` bits below. The order of a phase is the stable partition of the time order by group: by group, and by rank inside a group. A group is cut into blocks of at most `block_entries` entries, so phase `p` has `B_p = Σ_g ⌈n_p(g)/block_entries⌉` blocks over the groups with `n_p(g) ≥ 1` entries, which is at most `G_p + f·T/block_entries` for `G_p` such groups. Construction makes two passes over the chunks of cycles, taken in at most 64 contiguous ranges of chunks: the first counts the entries per range and per group of phase 0, and after an exclusive prefix of the counts the second forms `e_j` and writes each entry at its place with its rank, the dense ordinal of the entry among all entries in time order, which the exclusive prefix of the entries per range gives. The counts are dense over the `2^(a − w_0)` groups of phase 0, visited or not: `4·ranges·2^(a − w_0)` bytes, zeroed and prefixed, with `w_0 = a` and one group when `a < ℓ`. That is 256 KiB at `a = 20` and `ℓ = 10`, and 512 GiB at `a = 32` and `ℓ = 1`: the option sets them, and not the bound on `a`. The partition does not depend on how the ranges are cut. No pass of the core is a comparison sort.

*Initial words.* The initial RAM is the pairs `(index, word)` of its non-zero words, with indices strictly increasing and below `K`, as the witness holds them, and `RamCore` is the one owner of what they contribute. At construction it lifts each word once into a list `Init_0` of pairs `(cell, value)` in cell order, 20 bytes per pair. `Init_p` holds, for every cell `index >> ℓ·p` that has one, the initial words of the cell bound at the challenges of the earlier phases. At the change from phase `p` the list is bound once: each pair is multiplied by `eq` of the phase's challenges at its low `w_p` bits, read from a table of `2^w_p` entries, by `fmadd`, and the pairs of one next cell are reduced together: a lookup and an accumulation per pair of `Init_p` and a reduction per pair of `Init_(p+1)`, on a list that shrinks by `2^w_p` when it is dense and not at all when no two of its pairs share a cell. The pairs are validated and lifted in parallel, and a change cuts the sorted list into ranges of next cells whose reductions are independent, down to partial sums when the output is one cell. The new list is written beside the old one. No initial word is lifted twice, no pass visits the `K` words, and a group that no entry visits costs what its pairs cost. After the last phase the list is the one value `Init(z)`.

*Checkpoints.* A block has a checkpoint, the `2^w_p` cells of its group as they are strictly before its first entry: the pairs of `Init_p` that lie in the group, plus the increments of the stores in the earlier blocks of the group. The checkpoints of a phase are one arena of `2^w_p·B_p` cells, built before the phase's first round in two parallel steps. Every block sums the increments of its stores into its own zeroed cells. Then every group replaces, cell by cell and in block order, the sum of each block by the exclusive prefix of the sums that starts from the group's pairs of `Init_p`; this is parallel over the groups, and over ranges of cells inside a group of many blocks, so the last phase, which is one group, is not serial; a last phase of a few cells has as few ranges, and the options benchmark measures it. An arena is an exception to the two alternating buffers of the kernels spec, as the checkpoints of `RegistersCore` are: disjoint blocks bind their short arrays of cells in place, each on the worker that owns it, and the cells in use halve while the allocation stays until its release.

*A round* is one scan per block, with a state `M` copied from the block's checkpoint. At round `b` of phase `p` the cell `c` of an entry is the low `w_p − b` bits of `address >> (ℓ·p + b)`, and the round's challenge binds address bit `ℓ·p + b`. For an entry: `A·M[c]` goes to `s(0)` when `c` is even and `A·M[c ^ 1]` to the leading coefficient, which is `claim` plus that sum, as for the registers; a store then does `M[c] ^= D`. Blocks are independent, so the scan is parallel over blocks and merges by XOR. The bind of a challenge is applied exactly once to every `A`, `D` and checkpoint cell. Inside a phase it is applied at the start of the next round: the arena by pairs, and in the scan one multiplication of `A` by `eq(r, bit)` per entry and one of `D` per store. The last challenge of a phase is applied to `A` and `D` in the move of the phase change, and the arena of the phase is dropped unbound. The last challenge of the last phase is applied to no entry, increment or arena, which are dropped; it binds `Init_p`, as that of every phase does, into `Init(z)`, and the cycle tables are built from the memory trace. An entry is bound `a − 1` times.

*Phase change.* The entries move to the order of the next phase by one scatter to disjoint places, parallel over ranges of the old order. Into the last phase, which has one group, the place of an entry is its rank. Into an earlier phase, which exists when `a > 2ℓ`, the place of rank `t` is found as at construction, from counts per range of ranks and per next group over the addresses in time order, an array of 4 bytes per entry that construction writes only then. The arena of the next phase is built after the move, from increments that are bound through the last challenge.

*Cycle rounds.* After the last address round, one pass over the chunks of cycles writes `Ra[j] = eq(z, addr_j)`, as `address_column(memory, z)` does, and `RamVal(z, j)` as the running XOR of `Ra[j]·U[j]` over the stores of the chunk, started from zero, with the element of a cycle written before the product of a store at that cycle is added, and records the total of the chunk. An exclusive prefix of the `T/4,096` totals from `Init(z)` gives the value at the start of each chunk, and a second pass adds it to the elements of the chunk. Both passes are parallel over the chunks. `Ra` stays unbound for `into_address_column`: its first bind writes a buffer of `T/2`.

#### RAM output

Three tables over the RAM words are extended and bound separately: `Mask[k] = [k ∈ mask]`, `F[k] = lift(final[k] ^ io[k])` with `io` zero outside the mask, and `Io[k] = lift(io[k])`. The round polynomial of round `i` is `l(X)·q(X)` with `q(X) = Mask_i(X)·F_i(X)`, the product of the two tables bound at the challenges so far and extended in the current variable; it is not the extension of the product `[k ∈ mask]·F[k]`, which in the smallest case of the criteria is zero where the message is `X·(1 + X)^2`. `q(0)` and the leading coefficient of `q` are sums over the pairs of the window, and `q(1)` comes from the claim, or from its own sum when `l(1)` is zero (Packed rows, "Row rounds 0 and 1").

The core holds `Mask`, `F` and `Io` on a window, the cells of the current round that meet the mask: three full buffers and three half buffers, 72 bytes per cell of the mask, with room for the boundary cells, each of which carries the three as field elements. `F` and `Io` are built over the words of the mask in parallel. A pair with one cell in the window and one outside contributes through the outside cell's `F`, so before each round the window is aligned to pairs by adding at most one cell on each side. An added cell of round `i` lies wholly outside the mask: its `Mask` and `Io` are zero and its `F` is `fold_words` of its `2^i` final words at the challenges so far, a fold that is parallel over blocks of its words when the cell is large. The added cells are disjoint dyadic ranges that tile the complement of the mask, so every word outside the mask is lifted and folded exactly once over the `a` rounds, and after the last round the window is the one cell `F(z) = Final(z) + Io(z)`; the value returned is `F(z) + Io(z)`. An empty mask, `K..K` included, has no cell to start from, and its bounds need not name a word: the window starts from the cell of word 0 with `Mask = 0`, `Io = 0` and `F = lift(final[0])`, grows by the sibling at each round, and reserves those two cells.

#### Value evaluation

The factors are `lt` (the `SplitLt` of `split_lt(r_cycle)`, two multiplications per pair), `Rd` and `S` (one `LazyFoldedRa` over a private two-column `ChunkIndexSource` on the memory trace: column 0 is `rd_j` with the table `eq_table(a_reg, None)` and the bound 32; column 1 is `Some(0)` on a store, with the table `[1]` and the bound 1), `U` (shared and read in round 0; the first bind writes the core's own `T/2`) and `Ra` (owned; dropped at the first bind). Per pair the core forms three quadratics, `Q_1 = lt·Rd`, `Q_2 = lt·Ra`, `Q_3 = S·U`, nine multiplications, and uses `(1 + S)·U = U + Q_3`. The registers member is `Q_1·(U + Q_3)`; the RAM member is `c_val·Q_2·Q_3 + c_final·Ra·Q_3`, the two coefficients applied after the sum over the pairs. In the node form each product is accumulated at 0, at the nodes `F128::from_raw(2)` and `F128::from_raw(3)` and, for the two of degree 4, at infinity; `coefficients_from_nodes` recovers the message at degree 4 with the value at 1 from each member's claim. The two members share one core behind a lock, under the contract of the routers' cycle core (`Shared::transition` in `router/cycle.rs`). The shared state records the round it last computed as the pair of the round's index and the challenge that preceded it, and holds the raw sums of that pass: the node sums of `Q_1·(U + Q_3)`, of `Q_2·Q_3` and of `Ra·Q_3`, with no coefficient and no claim in them. If the probe selects the coefficient form, the state holds the raw coefficients of the same three products, and each member applies its coefficients and recovers the coefficient it omits from its own claim. A member that asks for round `i` after challenge `r` finds that pair, and nothing is bound or computed; or finds round `i − 1`, and the core binds once at `r` and makes the pass; or finds anything else, the same round after another challenge included, and gets the round error of `jolt-sumcheck`. Each member builds its message from the cached sums and its own claim. No member receives a polynomial recovered with the other's claim, and the order in which a scheduler visits the two changes no message, which the reverse scheduler of the criteria tests.

### Alternatives Considered

Counts are per cycle at `log_t = 22`; a saving is given at price point 1 and at price point 2.

- **An 8-byte record per cycle, built by a pass of this crate.** The index as a `u32`, three registers and the store bit: one read per cycle in place of `d_a + 4` bytes. It is a second gather of digits the walk has validated, `4 L + 12 w` by count, 2.2 ns per cycle, and a second copy of the RAM chunks, against 20 word operations per cycle to read the index from its bytes twice.
- **Registers read through the bytecode index.** A table of three registers per bytecode row, packed into a `u16`, 2 MiB at `2^20` rows, read at every cycle of six scans, against three sequential bytes. The register group costs the walk three comparisons with the row per cycle.
- **Registers through the entries of `RamCore`.** Three entries per cycle and a write on three cycles of four: `4 M + 6 A + 1 Bk` per address round against `1 M + 8 A + 2 R + 4 L + 1 Bk + 4 w`, which is 14.5 ns against 14.4 at point 1, 8.4 against 9.3 at point 2 and 9.3 against 10.4 at the loaded figures. The count does not decide; the 84 bytes per cycle of entries, against none, do.
- **The general form in the last register round.** `1 M + 8 A + 2 R` against the `3 M + 2 A` of the two cells: 4.3 ns more at point 1, 2.8 at point 2 and 1.4 at the loaded figures. Rounds 1 to 3 with their products bucketed unreduced by cell would save the reductions and store an accumulator per cell, whose price is not A; it is compared by measurement or not at all.
- **RAM in the scan form of the registers.** The state of a chunk would be `K` cells. Grouping by address is what bounds the state at `2^phase_bits` cells, and it needs the entries.
- **RAM with weights bucketed per cell.** Between two stores to a pair of cells the reads add their weights into a bucket, and a store multiplies the bucket out: `f Bk + s·(3 A + 1 Bk)` and a read-out of `0.375·f A` per round, against `2·f A + s Bk`. Over 20 rounds it saves 4.09 ns at point 1 and 0.64 at point 2 and loses 4.54 at the loaded figures. The sign turns on the price of a bucket update inside a block's state of 16 KiB, which no unit of the table measures in that layout. Rejected. What reopens it is a probe of one address round in both forms, on the entries of `local` in the block layout of `RamCore`, that finds the bucket form faster by more than the spread of repeated runs on 1 and on 12 threads.
- **One phase of `a` bits.** A checkpoint of `K` cells per block, 16 MiB at `a = 20`.
- **Dense tables of `K` elements in the output check.** `κ·(24 L + 5 M + 2 A)` and 72 bytes per RAM word, against `κ·(8 L + 1 A)` and 72 bytes per word of the mask.
- **Packed rows as dense tables from round 0, or from round 2.** 96 elements per cycle, 1.5 KiB; or 24 elements per cycle, 384 bytes, and three more multiplications per cell and round.
- **A third row round from statistics.** The products of a block of eight rows are sums of interactions of two digits, so no histogram over four digits is needed, but the pairs multiply: the eight power columns of one block need 28 histograms of two digits where its two blocks of four rows need 12. Those 16 more updates per cycle are 9.6 ns at point 1 and 13.4 at the loaded figure for one block, before the terms that join the gate block to the digits.
- **The gate's folded `Bz` kept from round 2.** One element per cycle, `(1 + r_0)·pack(word_0) + r_0·pack(word_1)`, written in the pass of round 2 and read in rounds 3 and 4 in place of the two words. Round 3 takes the later weights of the gate out of its sum over the cycles and saves its two multiplications. The last row round materialises the exact `Bz` of the first cell and still scales the kept element once per cycle, by `(1 + r_1)·(1 + r_2)·(1 + r_3)`, so it saves one. That is at most `−3 M` by count, 5.49 ns at point 1, 2.7 at point 2 and 4.77 at the loaded figures, and `−2 M` for a pass that scales the element in both rounds, for 16 bytes per cycle, 64 MiB at `2^22`, beside the tables of the core. Not decided here. The item of `outer_f128.rs` measures the core with and without it, reports the saving per phase with any accumulation it adds, and ships the faster (Execution).
- **Another binding order.** Cycle variables before row or address variables would change every count above; the order of a member's variables is the protocol's, and the question is outside this spec.
- **Five pairs in batch 6a.** `+ρ·(2 M + 2 A)`: 1.5 / 0.8 ns at `log_t = 22` and 5.9 / 3.2 at 20, and 48 MiB at `2^20` rows.
- **`Ra` recomputed for batch 5.** `+1 M + 2 L + 10 w` at `a ≤ 22`, 3.1 / 2.2 ns, for 16 bytes per cycle less between the two batches. Taken if memory becomes the constraint.
- **One split equality for the two read checks.** Both use `eq(r_3, ·)`; sharing saves 96 KiB and couples two members that are otherwise independent.

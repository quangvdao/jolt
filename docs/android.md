# Running `jolt-core` on Android

Jolt's CLI depends on desktop-only tooling (`rustup`, `tar`, filesystem writes under `~/.jolt`, etc.). To run proofs directly on Android, use the `jolt-android` FFI crate which provides a JNI (Java Native Interface) API for embedding Jolt in Android apps. This guide walks through the setup and integration process.

**Note:** The `jolt-android` crate currently provides a skeleton API. Full proof generation and verification requires additional implementation work (see `jolt-android/README.md`).

## 1. Prerequisites

1. macOS/Linux host with development tools
2. Rust toolchain with Android targets:
   ```bash
   rustup target add aarch64-linux-android
   rustup target add armv7-linux-androideabi
   rustup target add x86_64-linux-android
   rustup target add i686-linux-android
   ```
3. Android NDK (Native Development Kit):
   - Install via Android Studio → SDK Manager → SDK Tools → NDK (Side by side)
   - Or download from: https://developer.android.com/ndk/downloads
4. Environment variables:
   ```bash
   export ANDROID_NDK_HOME=$HOME/Android/Sdk/ndk/26.1.10909125
   # Adjust version to match your installation
   ```

## 2. Build configuration (already in repo)

- The `jolt-android` crate provides a JNI layer on top of `jolt-core`
- It uses the `prover` feature (which includes `minimal`) without the `host` feature
- `jolt-android/Cargo.toml` configures `crate-type = ["cdylib"]` so Cargo emits `.so` shared libraries
- Java wrapper code is auto-generated by the build script

## 3. Configure Cargo for Android NDK

Copy the template:

```bash
cp jolt-android/cargo-config.toml.template .cargo/config.toml
```

Or manually create `.cargo/config.toml` in the repository root:

```toml
[target.aarch64-linux-android]
ar = "aarch64-linux-android-ar"
linker = "aarch64-linux-android30-clang"

[target.armv7-linux-androideabi]
ar = "arm-linux-androideabi-ar"
linker = "armv7a-linux-androideabi30-clang"

[target.i686-linux-android]
ar = "i686-linux-android-ar"
linker = "i686-linux-android30-clang"

[target.x86_64-linux-android]
ar = "x86_64-linux-android-ar"
linker = "x86_64-linux-android30-clang"
```

The `30` in linker names refers to Android API level 30 (Android 11). Adjust for different minimum versions.

## 4. Cross-compile the native libraries

From the workspace root:

```bash
./scripts/build-android.sh
```

To also generate the Java wrapper:

```bash
JOLT_ANDROID_JAVA_OUT="$(pwd)/target/android/java" ./scripts/build-android.sh
```

Environment knobs:

| Variable | Default | Purpose |
| --- | --- | --- |
| `JOLT_ANDROID_PACKAGE` | `"jolt-android"` | Cargo package name to build |
| `JOLT_ANDROID_FEATURES` | `""` | Feature set passed to `cargo` |
| `JOLT_ANDROID_TARGETS` | `"aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android"` | Space-separated list of targets |
| `JOLT_ANDROID_BUILD_TYPE` | `release` | Use `debug` or custom profile name |
| `JOLT_ANDROID_JAVA_OUT` | _(unset)_ | Path to generate Java wrapper. When set, creates `JoltProver.java` |

Build outputs:

```
target/android/
├── jniLibs/
│   ├── arm64-v8a/libjolt_android.so       # ARM64 devices
│   ├── armeabi-v7a/libjolt_android.so     # ARMv7 devices
│   ├── x86_64/libjolt_android.so          # x86_64 emulator
│   └── x86/libjolt_android.so             # x86 emulator
└── java/
    └── JoltProver.java                     # Generated wrapper
```

## 5. The `jolt-android` JNI crate

The repository includes a `jolt-android` crate that provides a Java-compatible API:

```java
public class JoltProver {
    // Get library version
    public static native String getVersion();
    
    // Get build information
    public static native String getBuildInfo();
    
    // Generate a proof from an ELF binary
    public static native ProofResult prove(
        byte[] elfBytes,
        byte[] inputBytes,
        int maxInputSize,
        int maxOutputSize
    );
    
    // Verify a proof
    public static native VerifyResult verify(
        byte[] proofData,
        byte[] preprocessingData,
        byte[] expectedOutput
    );
    
    // Test function to verify JNI works
    public static native int testAdd(int a, int b);
}
```

**Current Status:** The crate compiles and exports the API, but `prove()` and `verify()` return `ERROR_NOT_IMPLEMENTED`. See `jolt-android/README.md` for implementation details and next steps.

## 6. Integrate inside an Android app

### Copy Libraries

```bash
cp -r target/android/jniLibs app/src/main/
```

### Copy Java Wrapper

```bash
mkdir -p app/src/main/java/com/jolt
cp target/android/java/JoltProver.java app/src/main/java/com/jolt/
```

### Use in Kotlin

```kotlin
import com.jolt.JoltProver
import androidx.lifecycle.lifecycleScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.launch

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // Test basic functionality
        val version = JoltProver.getVersion()
        Log.d("Jolt", "Version: $version")
        
        val sum = JoltProver.testAdd(5, 7)
        Log.d("Jolt", "5 + 7 = $sum")  // Should print 12
        
        // Proof generation (currently not implemented)
        lifecycleScope.launch(Dispatchers.IO) {
            val elfBytes = loadElfFromAssets()
            val inputBytes = "test".toByteArray()
            
            val result = JoltProver.prove(
                elfBytes,
                inputBytes,
                1024 * 1024,
                1024 * 1024
            )
            
            when {
                result.isNotImplemented() -> {
                    Log.w("Jolt", "Not yet implemented")
                }
                result.isSuccess() -> {
                    Log.d("Jolt", "Cycles: ${result.cycles}")
                }
            }
        }
    }
}
```

### Gradle Configuration (Optional)

To automatically use updated libraries:

```gradle
// app/build.gradle.kts
android {
    sourceSets {
        getByName("main") {
            jniLibs.srcDirs("../../target/android/jniLibs")
        }
    }
}
```

## 7. Runtime considerations

- **Memory**: Complex proofs can easily exceed 2–3 GB. Monitor memory usage and test on devices with varying RAM.
- **Threading**: Always run proof generation on background threads using Coroutines, WorkManager, or similar.
- **Battery**: Consider only running when plugged in for production apps.
- **Storage**: Use `context.filesDir` for any file operations, not hard-coded paths.
- **Permissions**: No special permissions needed (native library runs in app's sandbox).
- **Updates**: When upstream `jolt-core` changes, re-run the build script to refresh libraries.

## Architecture Support

The build script creates libraries for:

- **arm64-v8a** (aarch64-linux-android): Modern ARM64 devices (most phones since 2017)
- **armeabi-v7a** (armv7-linux-androideabi): Older ARM32 devices (budget phones, older devices)
- **x86_64** (x86_64-linux-android): 64-bit emulator and rare x86 devices
- **x86** (i686-linux-android): 32-bit emulator and legacy x86 devices

To reduce APK size, consider only including ARM64 or using Android App Bundles (AAB).

## Differences from iOS

| Aspect | iOS | Android |
|--------|-----|---------|
| **FFI Type** | C functions | JNI (Java Native Interface) |
| **Library Format** | Static (`.a`) | Shared (`.so`) |
| **Bundle Format** | `.xcframework` | `jniLibs/` directory tree |
| **Language Bridge** | Objective-C/Swift | Java/Kotlin |
| **Architectures** | 3 (arm64 + 2 sims) | 4 (arm64, armv7, x86, x86_64) |
| **Build Complexity** | Simpler (direct C) | More complex (JNI layer) |

## Troubleshooting

### "ANDROID_NDK_HOME not set"

Install Android NDK and set the environment variable:

```bash
export ANDROID_NDK_HOME=$HOME/Android/Sdk/ndk/26.1.10909125
```

Add to `~/.zshrc` or `~/.bashrc` to make it permanent.

### "Library not found" or "UnsatisfiedLinkError"

Ensure:
1. Libraries are in `app/src/main/jniLibs/` with correct ABI subdirectories
2. `System.loadLibrary("jolt_android")` uses correct name (no "lib" prefix, no ".so" extension)
3. Target device architecture matches one of your built ABIs

### "No implementation found for native method"

JNI function names must match exactly. If you changed the Java package from `com.jolt`, update the Rust function names:

```rust
// For package com.example.myapp
#[no_mangle]
pub extern "C" fn Java_com_example_myapp_JoltProver_getVersion(...)
```

### Linker errors during build

Update `.cargo/config.toml` with correct NDK linker paths and API levels.

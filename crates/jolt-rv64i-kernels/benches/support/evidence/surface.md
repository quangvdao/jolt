# Public support surface

Items are benchmark-local APIs, not crate library exports. Each public item has one entry; public fields are described with their owning type.

- `allocator`: counting-allocator module.
- `arithmetic`: fixed arithmetic operation streams for probes.
- `example`: the example dense product core.
- `gather`: shared compact-source gather diagnostic.
- `word`: word-monomial input and evaluator.
- `RunnerError`: typed CLI, pool, source, core, challenge-capacity, operation-count and sumcheck failures.
- `Summary`: phase or total distribution (`median`, `min`, `max`).
- `Summary::spread`: max minus min.
- `Summary::meets`: median at or below a fixed threshold.
- `Clock`: runner-owned wall clock for bench subphases.
- `Clock::start`: starts a subphase clock.
- `Clock::elapsed`: returns its elapsed `Duration`.
- `PhaseTimes`: preallocated sample duration slots.
- `PhaseTimes::set`: writes one named phase slot.
- `Case<V>`: record `name`, `variant`, ordered `phases`, phase indices nominated for `total`, optional size/thread `threshold` function.
- `Case::core`: four primary phases plus named extra phases; nominates the four primaries for total.
- `Record`: `id`, `log_t`, `threads`, `samples`, phase summaries, per-sample-sum `total`, allocation maxima.
- `Record::improves_on`: total-median gain exceeds the two spreads combined.
- `Record::print_comparison`: prints alternating-case comparison and spread decision.
- `Record::print_requirement`: prints one phase against its fixed requirement.
- `Record::print`: prints named phase statistics, total, allocation maxima and optional total threshold.
- `Record::print_phase`: prints one phase and optional model comparison.
- `seeded_challenges`: produces 256 reproducible single-core challenges outside measurement.
- `run_cases`: source-scoped preparation, warmed pools, interleaved fresh samples, allocation snapshots, inspection, summaries and reporting.
- `core_rounds`: canonical low-variable-first message/evaluation loop and terminal bind, with a borrowed seeded point.
- `CoreRun`: borrowed `challenges`, disjoint `rounds` and `finish` durations.
- `BatchRun`: owned `proved` batch result, disjoint `rounds` and `finish` durations.
- `run_batch`: four-phase real-batch entry over `run_cases`, retaining the batch result through the allocation snapshot.
- `run_core`: four-phase single-core entry over `run_cases`.
- `ProbeCase`: `unit`, `variant`, supported `profiles` and `minimum_threads` selection metadata.
- `ProbeKernel`: fresh operation-stream contract, requiring `Send`.
- `ProbeKernel::operations`: primary-pass operation count.
- `ProbeKernel::run`: performs the pass and returns its checksum.
- `ProbeKernel::chain_terms`: optional chain length for per-term reporting.
- `ProbeKernel::memory_layout`: optional `(bytes_per_array, arrays)` metadata.
- `ProbeKernel::lookup_layout`: optional lookup-layout metadata.
- `ProbeRecord`: full `id`, per-operation `median` and optional memory `layout`.
- `run_probe`: probe selection, configuration and reporting through the common sampling loop.
- `MachineryKernel`: fresh machinery-pass contract, requiring `Send`.
- `MachineryKernel::Error`: pass failure type implementing `StdError`.
- `MachineryKernel::operations`: pass operation count.
- `MachineryKernel::run`: performs the fallible pass and returns its checksum.
- `MachineryKernel::plan_construction_ns`: optional already-measured plan cost.
- `MachineryKernel::memory_bytes`: optional `(plan_bytes, scratch_bytes)` metadata.
- `run_machinery`: source preparation, separate construction/pass allocation intervals and common sampling.
- `allocator::CountingAllocator`: successful Rust allocation/reallocation and live-byte accounting over `System`.
- `CountingAllocator::live_bytes`: current requested live heap bytes.
- `allocator::AllocationAllowance`: permitted worker `allocs` and `bytes` slack.
- `allocator::RAYON_WORKER_ALLOWANCE`: fixed allowance for existing allocation acceptance checks.
- `allocator::AllocationMeasurement`: exclusive process-wide allocation interval guard.
- `AllocationMeasurement::begin`: snapshots the resident baseline and starts counters.
- `AllocationMeasurement::finish`: stops counters and returns incremental allocation statistics.
- `allocator::AllocationStats`: interval `peak_bytes`, `final_bytes` and successful allocation/reallocation `allocs`.
- `gather::GatherError`: invalid compact-source geometry/digits or lazy-column failures.
- `gather::CompactDigits`: row-major compact digit source implementing `ChunkIndexSource`.
- `CompactDigits::new`: validates and compacts validated digit columns once per source.
- `gather::GatherSample<S>`: measured `duration` and retained lazy `columns` for the allocation snapshot.
- `gather::measure_lazy_gathers`: five-column `lo_hi_all`, checksum reductions and first four binds, including materialisation.
- `gather::run_gathers`: interleaved five-column groups using compact source fixtures and a separate diagnostic record.
- `arithmetic::HotArithmetic`: multiplication, word, product, chain and reduction operation streams.
- `HotArithmetic::mul_x`: constructs the multiply-by-x stream.
- `HotArithmetic::word`: constructs the word-monomial stream.
- `HotArithmetic::product`: constructs the field-product stream.
- `HotArithmetic::chain`: constructs a chain with the requested term count.
- `HotArithmetic::reduction`: constructs accumulator reduction or its control stream.
- `HotArithmetic::operations`: counted operations per pass.
- `HotArithmetic::terms`: optional chain term count.
- `HotArithmetic::run`: executes the stream and returns its checksum.
- `example::ExampleError`: input-shape and final-value extraction failures.
- `example::DenseProductCore`: dense two-polynomial `ProveRounds` example.
- `DenseProductCore::new`: validates and owns two equal-size power-of-two inputs.
- `DenseProductCore::initial_claim`: dense product sum.
- `DenseProductCore::final_values`: extracts the terminal pair after all binds.
- `word::WordInput`: operands `a`, `b` and shifts `left`, `right`.
- `word::word_monomial`: evaluates the word arithmetic expression.

`Sample`, CLI options, warmed-pool construction and `collect_samples` are private. The obsolete `run_core_variants` and `CycleScale` APIs were removed after their last callers moved to `run_cases`.
